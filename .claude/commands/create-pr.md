# 建立 Pull Request 指令

建立新分支、提交變更，並送出 Pull Request。

## 行為說明

- 根據目前的變更建立一個新分支
- 使用 Biome 格式化所有修改過的檔案
- 分析變更內容，自動切分為合適的邏輯單位並建立多個 commit（若需要）
- 每個 commit 聚焦於一個單一的邏輯變更或功能
- 為每個邏輯單位建立具描述性的 commit message
- 將分支推送至遠端
- 建立包含摘要與測試計畫的 Pull Request
- 只需要描述這次的 PR 內容，不需要其他的描述
- 將分支合併到 $ARGUMENT

## 自動切分 Commit 的準則

- 依照功能、元件或關注點切分 commit
- 將相關的檔案變更放在同一個 commit
- 將重構與功能新增分開提交
- 每個 commit 應能獨立被理解
- 多個無關變更應分開成不同 commit
- 一律使用正體中文（繁體）撰寫 commit message
- commit message 使用約定式提交格式（Conventional Commits）

## 撰寫 Pull Request 描述

請根據這次的異動內容，撰寫 Pull Request 標題與描述，格式如下：

---

## Summary

- 列出這次修改的主要項目，逐點清楚列出功能與改動重點
- 若為 UI 調整、邏輯變動、重構、刪除功能等，也需明確說明

## How to test

- 說明要怎麼驗證這次改動是否正確
- 可包含頁面位置、操作步驟、輸入條件與預期結果
- 若有多種情境（成功、失敗、權限不足等），請分段列出

## 注意事項

- 是否需要更新 `.env` 或其他環境變數
- 是否需執行 migration、清資料、重新啟動服務等
- 是否會影響其他模組或功能
- 是否還有尚未完成的 TODO（可用註解標明）
